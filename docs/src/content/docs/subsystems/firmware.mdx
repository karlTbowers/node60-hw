All firmware runs on **Zephyr RTOS**, the core RTOS for Node60 (<Ref id="DEC-019" />). Each service below is a Zephyr thread or work item. Each device is its own devicetree node, using an upstream driver wherever one exists. Two devices need Node60 drivers: the TPS2HCS08A (three instances) and the TMP175.

Ownership is separated by service so network availability never weakens local protection.

| Service | Responsibility | Failure behavior |
|---|---|---|
| Power-state manager | RUN, controller-commanded shutdown, cold boot; coordinate outputs, log flush, and PHY sleep | Never command PHY sleep until every output is off and the flash flush has completed |
| Output manager | Commands, interlocks, retries, aggregate-current budget; services each switch's SPI watchdog well inside 400 ms | Hardware-off on reset; bounded retries; latch critical faults; a stalled bus or task turns that switch's outputs off (<Ref id="DEC-018" />) |
| Telemetry acquisition | Select SNS, sample ADC, average, calibrate, timestamp | Attach mode validity; never mislabel muxed data |
| T1S service | RMII/MDIO, link, PLCA, filtering, wake reason; bus termination state (end or drop) stored in flash, set by the controller, restored with one 10 ms relay pulse at every cold boot (<Ref id="DEC-017" />) | Loss of link does not disable local protection; the relay holds its state through sleep and reset |
| Supervision service | Windowed SWT service, reset-cause capture, CMU and TPS3702 fault reporting | Hard-locked watchdog; no service until startup checks pass; retain last reset cause |
| Diagnostics & NVM | FCB fault/event log; NVS energy and wake/sleep counters; calibration and identity | Ahead-erase during run; CRC/version every record; bounded pre-sleep page flush |

## Zephyr devicetree map

| Hardware | Zephyr node / compatible | Notes |
|---|---|---|
| U601 / U701 / U801 switches | `&lpspi4` / `&lpspi5` / `&lpspi3` (`nxp,lpspi`), child at `reg = <0>` | Node60 TPS2HCS08A driver. Mode 1, ≤ 8 MHz, `pcs-sck-delay` and `sck-pcs-delay` ≥ 45 ns. FLT/WAKE, SNS and NTC channels set per instance |
| IS25LP032D log flash | `&lpspi2` + `jedec,spi-nor` | FCB event log, NVS counters |
| INA228A-Q1, TMP175-Q1 | `&lpi2c0` + `ti,ina228`, `ti,tmp175` | Upstream INA228 driver. Node60 TMP175 driver: 12-bit conversions, ALERT (`TMP175_ALERT_L`, EIRQ 23) as a sensor trigger |
| SNS, NTC, BATT_MON | `&adc1`, `&adc2` (`nxp,s32-adc-sar`, `group-channel = "precision"`), `ntc-thermistor` | One channel group per ADC instance |
| LAN8670 PHY | `&emac0` (`nxp,s32-gmac`) + `microchip,t1s-phy` | RMII, PLCA settings from flash |
| Fault and IRQ lines | `nxp,siul2-gpio` interrupts through `nxp,siul2-eirq` | EIRQ 0, 1, 2 (switches), 6 (LM74910H), 17 (PHY), 23 (TMP175) |
| SWT, console | `nxp,s32-swt`, `&lpuart0` (`nxp,lpuart`) | |

## Recommended status frame

Node identity, uptime, **VBAT_RAW voltage**, **INA228 digital protected-rail voltage, total current, and power**, TMP175 NFET-bank temperature, RSENSE NTC temperature, three switch-package NTC temperatures, LM74910H FLT state, temperature-validity and I²t-blackout flags, six command states, six measured currents, six measured output voltages, reset cause, supervisor status, channel fault bitmap, link/PLCA state, wake reason, and monotonic sequence counter. Command frames include target node, channel mask, desired state, optional timeout, sequence counter, and an application-layer integrity check.

## Diagnostic flash log

Fit **IS25LP032D-JNLA3**, a 32 Mbit AEC-Q100 Grade 1 SPI NOR, on switched 3V3_MAIN (<Ref id="DEC-011" />). The capacity holds 65,536 fixed 64-byte records—about 1.8 years before wrap at 100 events per day. Although 16 Mbit is sufficient, 32 Mbit is the commodity availability sweet spot.

| Property | Rev A implementation | Design consequence |
|---|---|---|
| Geometry / endurance | 4 KB uniform sectors; 256-byte pages; 100,000 program/erase cycles minimum | Zephyr FCB circular buffer for timestamped events; NVS for energy and wake/sleep counters |
| Write timing | 0.8 ms maximum page program; up to 10 pages = ≤8 ms worst-case pre-sleep flush | Controller-commanded shutdown provides the flush window before PHY sleep |
| Erase timing | 300 ms maximum sector erase; suspend/resume supported | Ahead-erase during normal operation; never begin sector erase at sleep entry |
| Contents | Channel trip plus current, voltage, and temperature; OCP, thermal, UV/OV; wake/sleep counts; energy counters | Log readback is exposed through the T1S application interface |

## Operating states

<CardGrid>
  <Card title="RUN">
    All rails, MCU, full PHY, flash, oscillator, and diagnostics active. Outputs remain off until firmware validates configuration and receives commands.

    `ENTRY: T1S wake → cold boot → PHY re-init`
  </Card>
  <Card title="PARKED / TC10 SLEEP">
    Only LM74910H SLEEP, the nanopower LDO, and LAN8670 VDDAU remain powered. No logging occurs while parked.

    `WAKE: controller ECU over T1S only`
  </Card>
</CardGrid>

<Aside type="tip" title="Defined shutdown transaction">
The controller sends an application-level “go to sleep” message. The node then turns off all six outputs, flushes pending records, waits for page-program completion, commands LAN8670 sleep, and allows INH to collapse the rails. Bus-idle timeout is not used (<Ref id="DEC-007" />).
</Aside>
